## 1. 为什么需要这份文档

本项目的文档分两层交付时，评审常关注：

- 「你的需求分析在哪？」→ 见 **01**  
- 「你的大图在哪？」→ 见 **02**  
- 「用户需求怎么落到 PRD 的？」→ **本文**  
- 「Demo 和系统什么关系？」→ Demo = 切口 PRD 的实现  

此前 **产品 PRD 从切口功能写起**，系统层与需求分析**篇幅不足**，容易被认为「只有 Demo、没有前序」。本文补齐中间链路。

---

## 2. 设计过程总览

```
用户需求 (UN-xx)
    ↓ 归类、排优先级
系统机会 (01 §4)
    ↓ 模块划分
产品大图 (02)
    ↓ 选切口、定交互形态
方案构思 (本文 §3)
    ↓ 功能拆解、验收、AI 方案
切口 PRD（产品PRD.md）+ 可运行 Demo
    ↓ 实现
ContentBrief Chat Demo
```

## 3. 方案收敛（从大图到「对话助手」）

### 3.1 候选方案

| 方案 | 描述 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A | 纯知识库搜索站 | 快 | 无任务闭环 | 否决 |
| B | 纯 Brief 表单 wizard | 结构清晰 | 无多轮/引用 | 否决 |
| C | **统一对话助手** | 查+办一体；贴近企业助手范式 | 实现复杂度中 | **选用** |
| D | 嵌入飞书机器人 only | 贴近办公 | 演示成本高 | 作后续演进 |

### 3.2 切口能力绑定

| 用户需求 (01) | 方案能力 | PRD 章节 |
|---------------|----------|----------|
| UN-01 查调性 | knowledge_qa + RAG | PRD §4.1、知识库 |
| UN-02 出 Brief | brief_create + 模板 | PRD §4.3 Brief 结构 |
| UN-03 要引用 | 脚注 cite + Drawer | V2.4 |
| UN-04 要追问 | 槽位分析 clarifying | brief-slots |
| UN-05 人确认 | 导出 + 标记完成 | V2 FSM |
| UN-06 改 Brief | brief_refine + diff | V2.1 / V2.4 |

### 3.3 交互演进决策

| 版本 | 交互 | 理由 |
|------|------|------|
| V1 | Header 手动切换「问答 / Brief」 | 演示时易讲解 |
| **V2.5** | **单入口** + 意图自动识别 | 符合企业助手；与 M7 大图一致 |

## 5. AI 方案如何写入 PRD（试用情况）

| 环节 | 设计选择 | 文档/代码 |
|------|----------|-----------|
| 模型 | OpenAI 兼容 API（如 DeepSeek） | README、Vercel env |
| 检索 | 关键词 + 中文 bigram（V0） | `lib/knowledge.js` |
| 生成 | Prompt 分 QA / Brief / Refine | `lib/prompts.js` |
| 安全 | guardrail + 价格拒答 | `lib/guardrail.js`、`eval/` |
| 评测 | `npm run eval` + rubric | `测试说明.md`、`eval/cases/` |
